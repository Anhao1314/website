# Secure Demo BFF Integration v0.1

Phase 3 adds a private-preview website BFF without changing the marketing homepage or the FlowCredit backend. No production request, deployment, project configuration, real credential configuration or Git publication is part of this implementation review.

## Architecture and boundaries

```text
Browser /demo/
  POST /api/demo/chat { prompt }
  X-Demo-Access: manually entered preview code
       ↓
api/demo/chat.js                 HTTP envelope, request ID, sanitized errors, safe logs
server/demo-security.js         exact Origin and constant-time preview guard
server/demo-validation.js       raw byte limit, media type and strict input schema
server/flowcredit-client.js      fixed destination, server credential, timeout, no redirects/retry
server/demo-response.js          nested allowlists, types and known-secret filtering
       ↓
https://flowcredit-api.onrender.com/api/v1/chat
```

The browser never receives the upstream credential or hostname. The application does not store the preview code in localStorage, sessionStorage or cookies. It keeps the manually entered value in the current page's password input and clears it on navigation/page restoration. Requests omit browser credentials/cookies. The preview code is necessarily visible to its holder in their own browser request; it is separate from the server-only FlowCredit credential.

The three synthetic presets are **inputs only**. Neither their JSON file nor the embedded copy contains results. Keep the two copies aligned; `check` verifies equality. All successful results, including custom prompts, must come from the BFF. There is no fixture fallback on failure.

## Request contract

Only `POST /api/demo/chat`, with no query string, accepts `Content-Type: application/json` (optional UTF-8 charset). Other paths and arbitrary upstream overrides are rejected. Content encodings other than identity are rejected.

Body: `{ "prompt": "..." }`. It must be an object with exactly one own field, a string `prompt`. All extra fields are rejected, including `text`, `messages`, `content`, `modelConsent`, `draft`, `url`, `endpoint`, `headers` and `authorization`.

The body is limited to 16 KiB before JSON parsing by counted stream bytes, independently of Content-Length; its serialized parsed size is also checked. A body-read deadline of 5 seconds prevents indefinite reads. Trimmed prompt length is 1–3000 JavaScript UTF-16 code units, matching the textarea's maxlength behavior. Oversized raw bodies return 413; a parsed prompt longer than 3000 returns 400. Malformed JSON/UTF-8 returns 400. The original untrimmed browser textarea is preserved after an error.

## Server-only settings

`.env.example` contains only the five requested settings with blank credentials and disabled access. No `.env` is created or loaded automatically by this implementation. Future authorized preview setup must supply:

| Setting | Policy |
|---|---|
| `FLOWCREDIT_API_BASE_URL` | Exact `https://flowcredit-api.onrender.com`, optional final slash. Any other host, scheme, path, query, credentials or fragment fails closed. |
| `FLOWCREDIT_API_KEY` | Nonempty server-only value, no CR/LF. Never browser-prefixed or bundled. |
| `DEMO_ENABLED` | Must equal the literal `true`; missing/false disables access. |
| `DEMO_ACCESS_CODE` | Nonempty secret distributed privately to preview users. Use a long random ASCII value, distinct from the API credential. Never place it in source, HTML, fixtures, URLs or deployment commands/logs. |
| `ALLOWED_DEMO_ORIGINS` | Comma-separated exact origins, without paths/trailing slash/wildcards. Each preview deployment origin must be listed explicitly. |

No Origin is rejected by default in every mode. The handler factory has a test-only override that works only when both `allowNoOriginForTests` is explicitly true **and** the injected environment is `NODE_ENV=test`. The deployed entrypoint never enables this override.

Access-code comparison uses SHA-256 digests and `crypto.timingSafeEqual`, so comparison inputs have fixed length. Missing codes, invalid codes, disabled preview or absent configured codes return the same 401 envelope. Origin denial returns 403. There are no permissive CORS headers; OPTIONS returns 405.

This is a controlled shared-code preview, not user authentication or anonymous public access. Origin is not authentication. Public rate limiting, bot protection and durable per-user access are Phase 4 work; they have not been added here.

## Upstream policy

The server constructs one POST with only `{ prompt }` and three explicit headers: Accept, Content-Type and its own Authorization credential. It never forwards browser Authorization, Cookie, Host, X-Forwarded-For or X-Demo-Access. HTTP Host is generated by the HTTP client from the fixed server destination.

All redirects, including same-host redirects, are rejected via manual redirect handling and the non-2xx check. There is no automatic POST retry. A 25-second AbortController deadline covers both waiting for headers and consuming the response stream. The browser has a separate 35-second safety timeout and aborts on navigation. Failure/cancellation can still leave already-started upstream computation running; no automatic resubmission occurs.

## Allowed response

Success requires HTTP 2xx, JSON media type, at most 64 KiB of counted decoded response bytes, valid JSON, an object with `ok === true` and object `data`. Arrays/null are not objects for this contract. Current accepted business statuses are `insufficient-evidence` and `assessed`. Insufficient evidence remains HTTP 200.

The BFF returns `{ ok: true, requestId, data }`. It generates its own UUID; internal upstream request/session/assessment IDs are not forwarded.

Allowed `data` fields:

- Strings: `status`, `message`, `readinessStatus`, `decisionStatus`, `evidenceStrength`.
- `presentation`: text `title`, `summary`, `assessmentStatus`, `decisionStatus`, `evidenceStrength`; numeric partial scores under `availableScores`; optional numeric `fullScores.TAI`, `fullScores.CCI`, text `fullScores.riskGrade`; text-array `nextSteps`.
- `extractedDraft`: the current backend NL parser's nine fields: `taskType`, `gpuModel`, `gpuHours`, `revenueUsd`, `computeSpendUsd`, `repaymentRatePct`, `overdue30Pct`, `payingCustomers`, `top5ConcentrationPct`. No fields are invented or recomputed.
- `missingInputs`: bounded string array.
- `requiredActions`: bounded strings or objects restricted to `id`, `category`, numeric `priority`, `title`, `message`, `description`, `action`, string-array `fields`. Backend numeric priorities are preserved.

Unknown keys, nested headers, assessment internals, parser metadata, stack/environment fields and session IDs are dropped. Known configured credentials are redacted if echoed in allowed text; apparent credential/diagnostic/path material in allowed text fails closed. Allowed text and arrays have size/type bounds. The BFF does not recursively relay arbitrary objects. Additional backend fields require explicit allowlist review.

The UI renders values with textContent, not HTML. Structured Data shows only the sanitized `data`; the BFF request ID appears separately. Optional TAI/CCI/riskGrade are not required for success and are shown as Not Computable when absent. There are no replacement zeros or default grades. Required follow-up and missing fields come from the current response; R/C are labeled as declared/credible activity histories, not token input/output counts.

Contract shape was checked read-only against the backend's `agent/src/server.js`, `chat-response-v02.js`, `intake-v03.js`, `nl-draft-v01.js` and OpenAPI documentation. No backend files were modified or executed; the test response is a synthetic mock, not a captured live production result.

## Errors, cache and logs

Every application response includes `Cache-Control: no-store`, JSON content type and nosniff. No upstream response is cached.

| HTTP | Error code |
|---|---|
| 400 | DEMO_INVALID_INPUT |
| 401 | DEMO_ACCESS_DENIED |
| 403 | DEMO_ORIGIN_DENIED |
| 405 | METHOD_NOT_ALLOWED (Allow: POST) |
| 413 | PAYLOAD_TOO_LARGE |
| 415 | UNSUPPORTED_MEDIA_TYPE |
| 502 | DEMO_UPSTREAM_ERROR |
| 504 | DEMO_UPSTREAM_TIMEOUT |

Example timeout error:

```json
{
  "ok": false,
  "error": {
    "code": "DEMO_UPSTREAM_TIMEOUT",
    "message": "The assessment took too long. Please try again."
  }
}
```

The implementation also includes a generated requestId. It never returns exception messages, upstream error bodies or stacks. Browser error text comes from a fixed local message map, not arbitrary upstream strings. Error recovery keeps the description and uses a new BFF request when the user explicitly retries.

The fixed log schema contains timestamp, requestId, status, latency, optional upstream status and prompt length. Full prompts, responses, operating data, headers, exceptions and both credentials are never logged by application code. Future hosting/account observability settings must preserve this boundary; no such settings were configured in this phase.

## Static output and Vercel configuration

The site remains native HTML/CSS/JS without a frontend framework, transpiler or runtime dependencies. `build` only copies `index.html`, `assets/` and `demo/` into ignored `dist/`, preserving public URL structure. Server code, tests, docs, `.env` and dependency manifests are outside static output. This avoids publishing the repository root after adding server files.

The Node 24 function uses Vercel's documented Web Standard `fetch(Request)` export in `api/demo/chat.js`. Request bytes are read from the stream rather than a pre-parsed request helper. Vercel discovers `/api` functions alongside the static output. Function maxDuration is 35 seconds (5-second inbound body budget plus 25-second upstream deadline, with response overhead).

Routes are explicit: `/` remains the original homepage; `/demo` redirects to `/demo/`; `/demo/` rewrites only to `/demo/index.html`; `/api/demo/chat` is the function. There is no global SPA rewrite.

All routes receive nosniff, no-referrer and restricted Permissions-Policy. Demo uses a CSP allowing only same-origin scripts/styles/images/fonts/connections, with no frames, objects, base changes or form navigation. API responses use default-src none and frame-ancestors none. Dynamic DOM text and score widths were checked in the local browser under this CSP without console CSP errors.

**Homepage CSP debt:** the unchanged marketing homepage contains inline CSS/JS. This phase intentionally does not apply the Demo's restrictive CSP to `/`, which would break the baseline. A future scoped change can hash/extract its inline resources. Existing homepage overflow is also unchanged.

References: [Vercel Node.js function exports](https://vercel.com/docs/functions/runtimes/node-js), [vercel.json configuration](https://vercel.com/docs/project-configuration/vercel-json).

No Vercel CLI/project build or deployed routing test has been performed. The local harness exercises the same handler and security headers, but is not an emulator of the Vercel edge router. An authorized preview deployment must still verify platform routing, environment injection and cold-start timeout behavior.

## Reproducible local checks (no credentials or production calls)

Use Node 24. There are zero runtime and dev dependencies; the lockfile contains only the root package.

```sh
npm test
npm run check
npm run build
npm run dev:mock -- 8789 success 1200
```

When npm is unavailable, identical commands are:

```sh
node --test test/*.test.js
node scripts/check.js
node scripts/build-static.js
node test/local-e2e.js 8789 success 1200
```

The final arguments to the mock runner are port, mode (`success`, `error`, `invalid`) and artificial upstream delay in milliseconds. This delay exists only in the test harness, not the BFF or frontend. The mock runner generates disposable credentials in process memory, saves only the disposable local preview code to an owner-readable OS temporary file, and prints that file's path. Read the file and manually enter its content in the browser. Neither value is a production credential, is stored in the repository, or configures process/Vercel environment variables. Stop with Ctrl-C to remove the temporary file.

The harness creates two real HTTP listeners bound to loopback: website/BFF and a mock upstream on an ephemeral port. Its injected transport asserts the fixed target then connects **only** to that loopback mock. There is no branch that falls through to production fetch. The mock returns one official-case response for deterministic UI verification; it is not a replacement risk engine or parser. Mock modes must never be deployed.

Tests cover all 18 requested acceptance categories, additional method/query/body-stream/type checks, credential/header boundaries, safe logs, field allowlists, absent full scores, current-response rendering, no fallback, navigation cancellation, reduced-motion CSS, and real local HTTP. Check also scans browser assets and verifies input-only fixture copies, the environment template, routing and zero dependencies.
